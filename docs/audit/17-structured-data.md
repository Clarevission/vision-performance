# 17: Structured data

JSON-LD is generated by `lib/pages.js` from page front matter (`schema`, `breadcrumb`) and page-specific blocks.

| Page(s) | Types | Notes |
|---|---|---|
| `/` | `Organization` (name, URL, 512 px logo, email, telephone, `PostalAddress` Edmonton AB CA, `Brand` × 2 for SafetyOS/Mires), `WebSite` | No `LocalBusiness`: there is no public premises or opening hours to claim. The `telephone` value is the unconfirmed number (F-16), so remove it from `lib/pages.js` if the number is dropped |
| All inner pages | `BreadcrumbList` | Matches the visible breadcrumb |
| `/technology/safetyos`, `/technology/mires` | `SoftwareApplication` (category, operating system, product-site URL, description, publisher `Organization`) | No `offers`, `aggregateRating` or `review`, because no pricing or verified reviews exist |
| `/mobile-clinics`, `/solutions/prescription-safety-eyewear` | `FAQPage` | Questions and answers mirror visible on-page FAQ text |

## Verification

- `npm test` parses every JSON-LD block on every page.
- No markup claims anything the page doesn't show. There are no ratings, prices, opening hours or medical-clinic types.
- Recommended owner step: run https://search.google.com/test/rich-results on `/`, `/technology/safetyos` and `/mobile-clinics` after deploy. The audit machine had no browser session for that tool, so it was not run.

Google shows FAQ rich results only for authoritative government and health sites, so the FAQPage markup is kept for semantics and other consumers, not for SERP features.

No changes were needed in this audit.
